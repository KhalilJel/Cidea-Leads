# Cidea Leads — Homepage Redesign v2

## Direction

Cidea Leads should feel like a focused B2B lead-generation company, not a generic marketing agency.

Core idea:

> Vi finner kundene du faktisk kan selge til.

The homepage should communicate three things within the first screen:

1. We find relevant companies.
2. We qualify opportunities before sales time is spent.
3. The output is useful sales opportunities, not a generic database of contacts.

Visual identity: black, white and electric lime.

Design principle:

> Data clarity + commercial confidence + controlled energy.

The site should feel closer to a modern data product / revenue intelligence company than a traditional agency.

## Audience

Primary:
- Norwegian B2B companies that need more qualified sales opportunities.
- Sales-led companies with a defined target market.
- Companies that have sales capacity but need a better flow of relevant prospects.

Secondary:
- Small and medium businesses without a dedicated prospecting team.
- Companies entering a new vertical or geographic market.
- Companies that need targeted prospect lists and research.

Do not position the service as "more leads at any cost".

## Conversion principle

Every major CTA is a value mechanism.

Primary CTA:

**Få en uforpliktende vurdering**

Supporting copy:

**Ingen kostnad. Vi ser på målgruppen din og peker på hvilke salgsmuligheter vi mener er mest relevante.**

The CTA should open the existing email flow to jelassi@smartsvar.no. Do not introduce a form unless separately approved.

No "gratis" as the headline hook. The value and absence of obligation should be explicit in supporting copy.

## Visual system

### Colors

- Background: near-black
- Primary text: off-white
- Secondary text: muted grey
- Accent: electric lime
- Borders: subtle grey/green
- Cards: slightly lighter black than page background

Lime should be used selectively for key metrics, active states, small labels, CTA emphasis and data visualizations.

Avoid flooding the page with lime.

### Typography

Use a strong modern grotesk for headlines and body.

Use a monospace font sparingly for system labels, metadata, data points and small technical annotations.

Headline typography should be large and confident, with tight line-height.

### Layout

Desktop:
- generous horizontal margins
- strong 12-column grid
- asymmetric compositions
- large visual areas
- short text blocks

Mobile:
- single-column
- preserve hierarchy
- data visual becomes stacked cards
- no horizontal overflow
- CTA remains obvious

### Motion

Motion should communicate live data and system activity, not decoration.

Use:
- subtle number transitions
- line/path movement
- hover state changes
- card reveal
- small pulse on live system indicators

Avoid excessive parallax, generic floating blobs, slow ornamental animations and distracting scroll effects.

Respect prefers-reduced-motion.

**Det er lett å finne bedrifter. Det vanskelige er å finne de riktige.**

**En lang liste med selskaper er ikke nødvendigvis en god salgsbase. Verdien ligger i å finne bedrifter som faktisk passer målgruppen din, forstå hvorfor de er relevante og gjøre neste steg enklere.**

## Section: The system

Headline:

**Fra marked til salgsmulighet.**

Intro:

**Vi bygger prosessen rundt det som faktisk betyr noe: relevans, kvalitet og neste steg.**

Five stages:

### Find
Finn bedrifter som matcher målgruppen.

### Qualify
Vurder størrelse, bransje, geografi, digital tilstedeværelse og andre relevante signaler.

### Personalize
Finn konkrete grunner til at bedriften er relevant.

### Connect
Gjør det enkelt å starte en relevant samtale.

### Measure
Følg med på hva som fungerer og forbedre prosessen over tid.

Visual:
Horizontal pipeline on desktop.
Vertical pipeline on mobile.

Each stage should animate into the next as the user scrolls.

# Accessibility

- WCAG-conscious contrast
- visible keyboard focus
- semantic headings
- buttons/links with clear labels
- reduced motion support
- no color-only communication
- accessible mobile navigation

# Build rules

This redesign should be built as a clean visual system rather than patched section-by-section onto the existing homepage.

Reuse useful infrastructure:
- existing React/Vite setup
- routing
- SEO helpers
- sitemap/robots
- blog infrastructure
- deployment configuration

Do not:
- change DNS
- change MX
- remove existing domain configuration
- introduce a new framework without a reason
- invent client results
- invent testimonials
- add generic stock imagery
- create repetitive service-page sections

Before production deployment, validate:
- desktop
- tablet
- mobile
- navigation
- all CTAs
- email links
- SEO metadata
- sitemap
- build
- Netlify deployment

Production deployment should only happen after visual direction is approved.
